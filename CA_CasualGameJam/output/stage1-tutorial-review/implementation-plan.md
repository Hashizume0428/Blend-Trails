# ステージ1 チュートリアル実装設計案

作成日: 2026-10-24（Asia/Tokyo）
状態: 修正版画像を確認して具体案を整理済み。実装は未着手。
対象画像: [stage1-tutorial-preview-v2.png](stage1-tutorial-preview-v2.png)

この文書は後日の実装依頼に備えた設計資料です。コード、シーン、Prefab、ゲーム用画像、設定は変更していません。未指定の表示タイミングなどは推奨初期値として記載します。

## 1. 実現する動作

- ステージ1だけに、想定回答に沿って移動する指を表示する。
- 日本語のUIを追加しない。「指の動きをまねしてなぞろう」は追加しない。英語の説明文にも置き換えない。
- プレイヤーが別の経路・別の着色配置で条件を満たした場合も通常どおりクリアする。
- ガイドは表示だけを担当し、実際のタイルの着色、線の確定、クリア判定を操作しない。
- 画像の STAGE 1 TUTORIAL / RED GUIDE / BLUE GUIDE は比較資料の見出し。ゲーム画面に追加するラベルではない。
- 指、接触位置の薄い円、薄い点線、小さな矢印を今回の表示案とする。点線は専用ルートの強制を意味しない。

## 2. 既存構成の確認結果

実際のステージ1は Assets/Scenes/SampleScene.unity。
Stage01.unity というシーンは使用しない。

確認したシーン階層:

    GameCanvas
      SafeArea
        StageContent
          Level
          HomeButton
          BoardArea
          MixPurple
          ReloadPanel
      ClearPanel

GameCanvas は Screen Space - Overlay。
CanvasScaler の基準解像度は 1324 × 2879。
盤面のタイルは SpriteRenderer と Collider2D を使うワールド座標のオブジェクト。
StageScreenLayout が SafeArea、盤面の位置・スケール、クリア時の移動・縮小を調整している。

GameManager の Changed、State、IsInitialized、HasCommittedLine、GetTile、TilesList から必要な情報を読める。
GameManager 自体にチュートリアルの進行状態を追加する必要はない。

クリア判定は GameManager.StageClearCheck -> TileController.IsTileCorrect -> PuzzleRules.IsTileCorrect。
経路や想定回答との一致は見ていないため、この判定を維持する。

## 3. 推奨する構成

表示制御は新規の StageOneTutorialGuide にまとめ、専用のUI Prefabを盤面上に配置する。
ステージ1だけのため、汎用チュートリアルシステム、ScriptableObjectの解答カタログ、保存データは追加しない。

配置案:

    GameCanvas/SafeArea/StageContent/BoardArea
      StageOneTutorial
        GuideTrail
        DirectionArrow
        TouchHalo
        HandPointer

StageOneTutorial の RectTransform は BoardArea に合わせてストレッチする。
ルート表示、接触円、指の順に描画し、指が最前面になるようにする。
Canvas や EventSystem は増やさない。
ルートの GameObject と制御コンポーネントは有効に保ち、CanvasGroup の透明度で表示を切り替える。
入力中に制御コンポーネントまで無効化して、状態変更の通知を受け取れなくなる構成は避ける。

専用コンポーネントの責務:

- 現在案内できる色を既存ゲーム状態から決める。
- 指の移動、開始位置の接触表現、ループ、再表示待ち時間を管理する。
- 案内座標を実際のタイル位置に変換する。
- 操作、判定、画面遷移、アプリ中断時に表示を止める。
- OnDisable / OnDestroy で購読・再生処理を解除する。
- PuzzleId が1以外なら表示を無効にする。

## 5. 解答ルートの持ち方

ガイド用Prefabのコンポーネントに、赤・青それぞれの Vector2Int 配列をシリアライズして保持する。
実行時に Tests、Editor、output 内の資料を参照しない。

以下はUnity座標で、左上(0,0)、右がx、下がy。

赤:

    (0,0) (1,0) (2,0) (3,0) (4,0)
    (4,1) (3,1) (2,1) (1,1) (0,1)

青:

    (4,3) (3,3) (2,3) (1,3) (0,3)
    (0,2) (1,2) (2,2) (3,2) (4,2)

各10点を使い、隣接するタイル中心の間を一定速度で移動する。
4つの折れ点だけを同じ時間で補間して、長い横移動が急に速くなる構成にしない。
Builder は開始点、範囲、重複、上下左右の隣接、指定色との整合を検証して配置する。
将来盤面を変更した場合は、このルートも更新する。

## 6. 案内色と表示状態

下表は推奨する動作。案内は赤を優先するが、青から描く操作も許可する。

| 状況 | ガイドの動作 |
|---|---|
| ステージ1を開き、初期化が終わった | 少し待って赤をループ再生 |
| プレイヤーが描き始めた | 指・円・点線・矢印をすぐ非表示 |
| 指を離して判定中 | 非表示を維持 |
| 赤だけ確定し、その着色が想定回答の赤領域と同じ | 少し待って青を再生 |
| 青だけ先に確定し、その着色が想定回答の青領域と同じ | 少し待って赤を再生 |
| 確定済みの着色が想定回答と異なる／不完全 | 矛盾するガイドは表示しない。通常の入力とクリア判定を続ける |
| 両色を確定したが未クリア | ガイドは非表示。既存の誤り表示とリセットを利用する |
| 全リセット | 待機後に赤から再生 |
| 色別リセット | 残った色の着色を確認し、案内可能なら未確定色を再生 |
| ストローク取消 | 取消後の盤面を確認し、案内可能なら待機後に再開 |
| クリア判定・クリア演出・クリア後 | 非表示。次の画面へ持ち越さない |
| HOME・シーンロード・アプリの一時停止やフォーカス喪失 | 停止・非表示 |
| 復帰 | 盤面を再評価してから待機後に再開 |
| PuzzleId が1以外 | 常に非表示 |

「着色が同じ」は経路の一致ではない。
例えば赤が想定回答と違う順番で上2行を塗り切っていても、青のガイドを表示する。

一方、赤を上2行以外へ伸ばした状態で、下2行の青ガイドをそのまま見せると紫や塗り残しを誘導し得る。
この場合は表示だけを止める。
プレイヤーの線を戻す、強制的にリセットする、誤った操作として拒否する処理は追加しない。
別解用のルート自動探索も初期実装には含めない。

案内の可否は、Idle時に全20マスの CurrentColor と確定済み色を照合して決める。
未確定色の領域は未着色であり、確定済み色は想定領域を過不足なく単色で塗っていることを確認する。
この照合結果はガイド表示のみに使用し、クリア条件には接続しない。

GameManager.Changed を受けて表示状態と再開待ちを更新する。
毎フレームの移動では経過時間と表示位置だけを更新する。
再描画・タイル通知のたびに再生ループを二重起動しない。

## 7. アニメーションの推奨初期値

以下は画像からは決まらないため、Inspectorで変更できるようにする。

| 項目 | 初期値案 |
|---|---|
| 入場後の待ち | 0.8秒 |
| 開始点での接触表現 | 0.4秒 |
| 1マス移動する時間 | 0.28秒 |
| 終点での待ち | 0.4秒 |
| ループ間隔 | 0.8秒 |
| 操作・リセット後の再開待ち | 1.5秒 |
| 指の大きさ | タイル幅の約0.8倍を基準に調整 |
| 点線 | 実線の描画と区別できる薄さで、全ルートを表示 |

移動は直線的に行い、折れ角でタイルの外を横切る曲線補間は使用しない。
終点から開始点へ指を横切らせず、一度非表示にして開始点に戻す。
Time.timeScale に依存しない経過時間を使い、中断・復帰時は位置を飛ばさず再開待ちからやり直す。
見た目だけで説明し、新しい文章やステップ送りボタンは追加しない。
ステージ1に入るたび表示する案とし、表示済みフラグは保存しない。

## 8. 座標・描画・入力

指先を画像中央からの目分量で合わせず、手画像の指先を基準点にする。
RectTransform のpivotまたは子オフセットで、変換したタイル中心と指先を一致させる。

変換の流れ:

    タイルの transform.position
      -> 盤面Cameraによるスクリーン座標
      -> StageOneTutorial のローカル座標
      -> 指先・点線・矢印の表示位置

Overlay Canvas側のローカル座標変換はカメラなしで行う。
固定スクリーンピクセルではなく、投影した隣接タイル中心の間隔を手や点線のサイズ基準にする。
StageScreenLayout の既存レイアウト更新後に位置を反映し、画面サイズやSafeAreaが変わったら再投影する。
画面を開いた直後は盤面初期化・最初のレイアウトが完了してから表示する。

点線はプールした UnityEngine.UI.Image で表現する案とする。
毎フレームの生成・破棄を避け、表示色と必要な位置を更新する。
専用の LineController やゲームの合成線描画は呼び出さない。

全てのガイド用 Image は raycastTarget=false。
CanvasGroup は blocksRaycasts=false、interactable=false。
ルートに透明な入力用GraphicやButtonを置かない。

理由: InputTouchManager.BeginPointer は EventSystem.RaycastAll の結果が1件でもあると盤面入力を開始しない。
ガイド上からタップしたときも、既存タイルへの入力がそのまま通ることを実際に検証する。

## 9. シーン生成処理との整合

ReferenceStageBuilder.BuildStages は、存在しないシーンをステージ1のコピーから作る。
ステージ1に置くだけでは、将来のシーン追加時にガイドも複製される可能性がある。

StageOneTutorialBuilder に冪等な配置処理を設ける。

- PuzzleId が1なら、専用ルートを1つだけ配置し必要な参照と設定を揃える。
- 1以外なら、この機能の専用ルートがある場合だけ除去する。
- 他のUIや盤面の子は削除しない。
- 既存ルートを再利用し、何度適用しても増殖させない。

ReferenceStageBuilder.BuildStages では、ApplyBoard と UpdateClearScreen により問題IDと盤面が決まった後、保存前にこの配置処理を呼ぶ。
実装時の初回反映はステージ1専用メニューで行い、全30シーンを作り直す必要はない。
実行時の PuzzleId==1 判定も残し、複製された場合の二重対策とする。

## 10. 実装時に行う検証

今回テストコードは作成しておらず、Unityでのテスト実行もしていない。
以下を実装後の受け入れ確認とする。

1. ガイドを1ループ再生しても、タイルは未着色、確定色なし、クリアしていない。
2. 指・点線の上から、マウスとタッチ相当の入力で開始点を選べる。
3. 想定回答で通常どおりクリアし、クリア演出中にガイドが残らない。
4. 青から描いた場合も操作でき、赤の案内へ移れる。
5. 経路の形だけ違う解答、最終着色の分担も違う解答、どちらもクリアする。
6. 操作開始、取消、全リセット、色別リセット、中断・復帰、HOMEで表示が正しく切り替わる。
7. ガイドと一致しない部分着色をガイドが上書きせず、通常のゲーム状態を維持する。
8. ステージ2・30・エクストラで表示されない。シーン生成処理を再適用しても他ステージに増えない。
9. 縦画面の複数アスペクト比・SafeAreaで指先がタイル中心に合い、手や点線が切れない。

別の着色分担も許容する確認用解答。表記は行列を各1桁で表す1始まり:

    赤: 11 21 22 12 13 23 24 14 15
    青: 45 44 43 42 41 31 32 33 34 35 25

赤9マス・青11マスで全20マスを覆い、重複なし。
赤指定15/21、青指定41/35を満たし、隣接・開始点・同色での重複通過の制約にも適合する。
赤の確定後は想定回答の青ガイドを隠し、この別解の青ルートで既存のクリア判定が成功することを確認する。
座標上の整合性は今回確認済み。Unity実行での確認は実装時に行う。

## 11. 実装依頼を受けた後の作業順

1. 指・接触円・矢印の透過素材を用意し、専用Prefabを構成する。
2. StageOneTutorialGuide の表示専用制御を追加する。
3. ステージ1専用Builderと、ReferenceStageBuilderへの配置処理呼出しを追加する。
4. SampleSceneに反映し、既存ルールを保ったまま受け入れ確認を行う。
5. 仕様ドキュメントを更新する。

現行のステージシーンは旧Figmaスキンであり、比較画像は採用済みポップ調を基にした将来イメージ。
チュートリアル追加に合わせてゲーム全体のスキンを自動的に差し替えることはしない。
実装依頼時に最新のUI反映状況を確認し、指の素材と大きさを実際の盤面に合わせる。
